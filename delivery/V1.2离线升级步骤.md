# 已部署 V1.1 升级到 V1.2

V1.2 新增 Excel 批量导入、预览检查、模板下载及逐台导入日志。沿用当前可用的 UOS、Docker 和数据卷。宿主机不需要 Python，不需要联网，也不需要重新安装 Docker。

下列命令使用默认容器名 `asset-console-web`、`asset-console-monitor` 和数据卷 `asset-console-data`。如以前自定义过这些名称，升级时必须使用原名称和同一数据卷。

请逐步执行，出现报错时先处理该步骤，再继续下一步。

## 1. 解压并导入新镜像

将部署包和校验文件带到 UOS，打开所在目录终端，执行：

```sh
sha256sum -c asset-console-docker-1.2-arm64-offline.tar.gz.sha256 &&
tar -xzf asset-console-docker-1.2-arm64-offline.tar.gz
cd asset-console-docker-1.2-arm64-offline
sha256sum -c asset-console-1.2-arm64.image.tar.gz.sha256 &&
sudo docker load -i asset-console-1.2-arm64.image.tar.gz
```

应看到 `Loaded image: asset-console:1.2-arm64`。导入镜像不影响正在运行的旧容器。

## 2. 复制原配置并备份

将旧部署目录中实际使用的 `deploy/docker.env` 复制到新目录的 `deploy/docker.env`。也可以在文件管理器中复制；不要用示例配置覆盖原来的服务器 IP、端口等设置。下列路径需要换成你实际的旧目录：

```sh
cp "/实际的旧目录/asset-console-docker-1.1-arm64-offline/deploy/docker.env" deploy/docker.env
chmod 600 deploy/docker.env
sudo docker exec asset-console-web python scripts/backup.py
```

备份命令会输出备份文件路径，例如 `/data/backups/assets-日期时间.sqlite3`。升级前确认出现“备份完成”。备份保存在原数据卷，建议根据屏幕输出用 `docker cp` 再复制到服务器另一个受控目录；完整方法见 Docker 离线部署指南。

本次只新增导入批次表，原资产、账号、日志、密钥继续使用原数据卷。仍应保留升级前备份，以便需要时恢复。

## 3. 停止旧容器并启动新版

仍在新的 `asset-console-docker-1.2-arm64-offline` 目录中执行：

```sh
sudo sh deploy/docker-down.sh && sudo sh deploy/docker-up.sh
```

这会有短暂停机。新脚本默认启动 `asset-console:1.2-arm64`；停机脚本只删除两个业务容器，保留数据卷。若此前在当前终端设置过 `APP_IMAGE` 指向旧版，执行启动时显式指定新镜像：

```sh
sudo env APP_IMAGE=asset-console:1.2-arm64 sh deploy/docker-up.sh
```

等待 Web 就绪后浏览器刷新，左侧版本应为 `V1.2`。用原账号登录，进入「资产台账 → 批量导入」。无需再次创建管理员。

## 4. 核对运行与数据

```sh
sudo docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
sudo docker logs --tail 50 asset-console-web
sudo docker logs --tail 50 asset-console-monitor
```

Web 应为 `Up ... (healthy)`，检测容器为 `Up ...`。启动脚本按镜像 ID 启动，所以列表中镜像可能显示 SHA256；可用下列命令核对实际 ID 一致：

```sh
sudo docker inspect --format '{{.Image}}' asset-console-web
sudo docker image inspect --format '{{.Id}}' asset-console:1.2-arm64
```

核对旧资产数量、账号、操作日志和导出仍正常，再下载模板做小批导入。保留旧镜像和升级前备份，不执行删除数据卷的命令。

若新版启动失败，先保存 Web、检测容器日志。需要回退时，用 `docker-down.sh` 停止新版，然后以原配置执行：

```sh
sudo env APP_IMAGE=asset-console:1.1-arm64 sh deploy/docker-up.sh
```

本次数据库仅新增独立表，V1.1 会忽略该表；回退后看不到批量导入入口，但已新增的资产仍作为普通资产保留。若需要撤销已经导入的数据，应逐台核对删除，或按完整指南停机恢复升级前备份；恢复备份会撤销备份后的所有业务变更。
