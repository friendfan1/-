- 已实际构建 Linux ARM64 镜像，包含 Python 3.12.11、Django 5.2.18、全部 Python 依赖、本地静态资源及系统 Ping。镜像采用 Debian Bullseye/glibc 2.31 基线，以适配旧 Docker 默认 seccomp 对新系统调用的限制。
- Bullseye 已冻结，当前 security 索引引用的 libcap 修订文件返回 404；镜像明确选择仍存在且经签名仓库校验的 main 版本 `libcap2/libcap2-bin 1:2.44-1`，没有关闭签名、校验、TLS 或安装不存在的 security 修订。
- ARM64 镜像在 QEMU 显式模拟执行下通过 **47 项应用测试**；另通过空库／空账号、资产审计、实际 Waitress 多线程服务、实例健康检查、大屏、本地 CSS、匿名 XLSX 下载功能检查。模拟器仅用于构建和验证，不包含在交付镜像内。
- 原生 AMD64 同配方测试镜像使用官方 Moby **v18.09.1 默认 seccomp 文件**运行，47 项应用测试及线程创建通过；非 root、仅保留 NET_RAW 的 Ping 回环检测通过。它证明该安全策略组合下的行为，不等于旧版 daemon 或 ARM64 原生实机验收。
- 镜像内普通应用 UID/GID 为 `10001:10001`，初始 `/data` 为空，无默认账号。已在导入后的 ARM64 镜像读取到 `/bin/ping cap_net_raw=ep`。Web 去除额外能力，monitor 仅保留 NET_RAW；没有使用 privileged 或关闭 seccomp。
- 开发环境另有 **22 项脚本测试通过**：11 项 Docker 启停／入口保护、4 项镜像归档校验、6 项备份恢复测试、1 项真实 HTTP 服务 SIGTERM 生命周期检查。镜像缺失或架构错误时拒绝运行，不会隐式拉取；停机保留数据卷。
- Docker 容器版在真实 Chrome 83 中追加 **23 项浏览器检查通过**：免登录查看与导出、登录维护、增改删、逐字段日志及页面布局；无外部资源请求、无 JavaScript 异常、无资源加载失败。
- Host 网络的就绪检查会核对本次启动的实例标识，避免将同端口的其他服务误认成本系统。monitor 禁用仅适用于 Web 的镜像健康检查。
- 原生测试容器完成 **27 项实际生命周期与恢复断言**：在线一致性备份、修改、停删容器、复用原卷重建、离线一次性工具容器恢复、账号与审计日志恢复、密钥保持，以及后台 Ping 队列；没有输出密码、密钥或其指纹。

## Ping 的验证边界

检测逻辑覆盖在线、无响应、无 IP、组件缺失、权限不足、结果过期和 IP 变化后结果失效。使用官方签名仓库校验下载的真实 ping 组件对回环地址检测，确认云实例缺少所需 ICMP 权限；应用将该情况标为“检测异常”，没有误报为“未响应”或在线。

尚未连接单位工作网，也没有对单位真实终端进行探测。实际工作网在线检测须在目标 UOS 上以运行账号确认路由、防火墙和 ICMP 权限后验收。

## 离线与目标平台

离线安装流程已在全新临时虚拟环境中，以禁止包索引的方式从包内 wheels 安装，并完成迁移、静态文件收集、配置检查和备份恢复验证。交付包含纯 Python 依赖，不包含 Python 运行时或系统 ping；目标机须准备 Python 3.11+（建议 3.12）及对应系统组件。
